# verify-build

변경한 모듈의 빌드, Lint, 유닛 테스트를 돌려 종료 코드로 판정한다. **고치지 않는다.** 이 스킬은 쓰기 도구가 없는 에이전트로 돈다. 셸로 파일을 쓰는 것도 하지 않는다.

{{> impl-input}}

인자에서 feature, 작업 ID, 모듈 목록, 돌릴 테스트 작업을 읽는다. 모듈이 없으면 breakdown에서 작업의 경로로 모듈을 찾는다.

## 규칙

- **게이트는 좁게 둔다.** 인자의 모듈만 대상으로 한다. 프로젝트 전체를 돌리지 않는다. 마지막 확인으로 불렸을 때만 인자에 feature의 모든 모듈이 온다.
- **커버리지는 게이트가 아니다.** 통과와 실패만 판정한다.
- **검증하지 못한 것은 통과가 아니다.** 태스크가 없거나 환경 문제로 돌리지 못한 검사는 `skip`으로 따로 적는다.
- **실패를 분류한다.** 이번 구현이 만든 실패, 환경 문제(SDK 없음, 네트워크), 이전부터 있던 실패로 나눈다. 이전부터 있던 실패인지는 실패한 파일이 작업의 경로 밖이고 이번 변경과 무관할 때만 그렇게 본다. 확신이 없으면 이번 구현의 실패로 둔다.
- **근거 없는 지적은 하지 않는다.** 로그에서 파일과 줄을 지목할 수 있는 것만 보고한다.

## 실행

모듈마다 차례로 돌린다. 출력이 길면 마지막 부분과 `error:`, `FAILED` 줄만 본다.

1. **빌드**: `./gradlew {모듈}:compileDebugKotlin` (Android 모듈) 또는 `{모듈}:compileKotlin` (JVM 모듈). 테스트 소스는 포함하지 않는다. 테스트를 돌리는 경우에만 테스트 소스의 컴파일을 포함한다.
2. **Lint**: `docs/constitution.md`나 `docs/wiki/conventions/`에 Lint 명령이 적혀 있으면 그것을 쓴다. 없으면 프로젝트에 설정된 것을 순서대로 찾는다: `detekt`, `ktlintCheck`, `lintDebug`. 어느 것도 없으면 `skip`이다. 자동 수정 옵션(`--auto-correct`, `ktlintFormat`)은 쓰지 않는다.
3. **테스트**: 인자에 돌릴 테스트 작업이 있을 때만 `./gradlew {모듈}:testDebugUnitTest` (JVM 모듈은 `:test`)를 돌린다. 그 테스트 작업의 경로(breakdown의 작업 줄)에서 테스트 클래스를 읽어 `--tests '*{클래스 이름}'`으로 **그 클래스만** 돌린다. 모듈 전체를 돌리면 다른 작업의 실패가 섞여 이 작업의 게이트가 아닌 것을 판정하게 된다. 모듈 전체는 마지막 확인(인자의 테스트가 `전체`)에서만 돌린다. 실패한 테스트의 이름과 메시지를 모은다. 테스트 실패의 「실패 파일」은 실패한 테스트 클래스의 파일이다. 원인이 구현에 있어 보여도 구현 파일을 대신 적지 않는다. CLI가 테스트 파일로 테스트 작업을 찾아 횟수를 매기고, 고칠 파일은 치유 스킬이 정한다. 테스트 작업이 "없음"이면 테스트는 돌리지 않고 `skip`이 아니라 **적지 않는다**(아직 돌릴 때가 아닌 것이지 건너뛴 것이 아니다).

같은 명령을 다시 돌려 결과가 바뀌기를 기대하지 않는다. 한 번씩 돌린다.

## 보고의 형식

마지막 메시지가 보고다. `{{skill:impl-orchestrator}}`가 이 보고를 그대로 CLI에 넘긴다.

```text
결과: build=pass|fail, lint=pass|fail|skip, test=pass|fail (테스트를 돌린 경우만)
실패 분류: 이번 구현 | 환경 | 이전부터 (실패마다)
실패 파일: 저장소 루트 기준 경로를 쉼표로. 없으면 없음
증상: 실패를 한 줄로 (CLI의 --symptom에 들어간다)
실패 요약: 종류마다 오류 메시지와 위치를 다섯 줄 안으로
건너뛴 사유: skip이 있을 때
```

환경 문제로 돌리지 못했으면 그 검사를 `skip`으로 적고 사유를 쓴다. 통과로 꾸미지 않는다.
