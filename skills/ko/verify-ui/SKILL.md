# verify-ui

구현된 UI를 디자인과 대조한다. **고치지 않는다.** 이 스킬은 쓰기 도구가 없는 에이전트로 돈다. 셸로 코드를 쓰는 것도 하지 않는다. 캡처 파일을 `.sdd-android/impl/{feature}/captures/` 아래에 받는 것만 예외다.

대조는 두 가지다. 어느 것을 할지는 인자의 `대조:`가 정한다.

- **값의 대조**(UI 작업마다): 코드에 적힌 값과 구조를 Figma 노드와 대조한다. 토큰, 치수, 색, 타이포, 문구, 배치 순서, 상태의 표현을 본다.
- **캡처의 대조**(단위가 끝날 때, 마지막 확인): 기기에 띄운 Compose 프리뷰의 캡처를 Figma의 기대 이미지와 대조한다. 누락, 순서, 상태 표현처럼 그려진 결과에서만 보이는 것을 본다.

## Figma 서버

!`sh "$(git rev-parse --show-toplevel)/.sdd-android/bin/sdd-android" figma show`

위에 적힌 도구 이름을 그대로 쓴다. 도구 목록에 지연 로드 상태로만 있으면 ToolSearch로 불러온 뒤 쓴다. 읽기 도구만 쓴다.

## 판정 규칙

- **독립적으로 다시 읽는다.** `{{skill:create-ui}}`의 보고나 `.sdd-android/impl/{feature}/design.md`를 근거로 삼지 않는다. Figma 노드를 직접 다시 연다.
- **항목별로 대조한다.** 구성요소, 문구, 색상 토큰, 타이포, 배치 순서와 간격, 상태 표현. 픽셀 비교는 하지 않는다.
- **심각도를 매기지 않는다.** 어긋난 것은 모두 차이 목록에 올리고, 하나라도 있으면 `fail`이다.
- **열지 못한 노드는 미검증이다.** 통과와 섞지 않는다. 권한 오류와 한도 초과는 "열리지 않는 노드"와 구분해 오류 문구를 그대로 적는다. 응답 없음으로 중단된 호출(`sent no response or progress`)은 한 번 더 부른다. 서버가 첫 호출의 일을 이어 가서 두 번째는 바로 돌아오는 때가 많다.
- **Figma의 주석은 화면이 아니다.** `get_screenshot`에 찍힌 번호 표시, 흐름 화살표, 선은 Figma의 주석이다. 구성요소로 세지 않는다.
- **노드가 없는 작업은 건너뜀이다.** 인자의 노드가 "없음"이면 대조하지 않고 `skip`과 사유(대조 대상 없음)를 적는다.
- **토큰 판정**은 constitution이나 규약 문서가 정한 기준을 따른다. 정한 것이 없으면 "값이 같은 토큰이 있는데 실측값을 썼다"만 차이로 본다.
- **근거 없는 지적은 하지 않는다.** Figma의 노드와 값, 코드의 파일과 줄을 함께 지목할 수 있는 것만 차이다. 캡처의 대조에서 색과 크기를 지적하려면 `get_variable_defs`로 읽은 변수 값과 코드의 토큰을 함께 지목한다. 스크린샷의 눈대중만 있는 것은 차이가 아니라 미검증이다.
- **spec이 Figma와 다르게 정한 것은 차이가 아니다.** `docs/specs/{feature}/spec.md`가 자산이나 문구를 명시해 두었으면(예: "일러스트는 `tutorial_mascot_step_1` 자산을 쓴다") 그 항목은 spec대로 구현된 것을 확인하고 「spec이 정한 차이」에 적는다. 차이 목록에 올리면 `{{skill:create-ui}}`가 고칠 수 없는 것을 고치려 든다.

## 값의 대조

1. 인자의 노드를 `get_metadata`, `get_variable_defs`, `get_design_context`로 읽는다. 컴포넌트 작업이면 화면 노드에서 해당 자식으로 내려간다.
2. 인자의 파일(작업이 바꾼 파일)을 읽는다. 구성요소의 트리, 문구, 색과 타이포, 간격과 크기, 상태별 분기를 추린다.
3. 항목별로 맞댄다. 차이마다 노드와 값, 파일과 줄, 무엇이 다른지를 적는다.

## 캡처의 대조

셸 명령은 **한 번에 하나씩** 부른다. `adb`, `emulator`, `./gradlew`를 `;`나 `&&`로 다른 명령과 묶지 않는다. 허용 목록은 명령 단위로 맞춰져 있어, 묶음의 한 부분이라도 허용 밖이면(따옴표 인자, `grep`, `git`) 묶음 전체가 거부되고 기기 명령까지 실행되지 않는다. 에뮬레이터를 띄우는 명령은 그 한 줄만 백그라운드로 부른다.

1. **기기**: `adb devices`로 연결된 기기를 본다. 없으면 `emulator -list-avds`로 이미 만들어진 가상 기기를 찾아 화면 없이 띄운다(`emulator -avd {이름} -no-window -no-audio &`, `adb wait-for-device`, 부팅 완료는 `adb shell getprop sys.boot_completed`가 `1`). 가상 기기가 없으면 만들지 않는다. 기기도 가상 기기도 없으면 캡처의 대조는 `skip`(기기 없음)이고 끝낸다.
2. **빌드와 설치**: 인자의 앱 모듈을 디버그로 빌드해 설치한다(`./gradlew :{앱 모듈}:installDebug`). flavor가 있어 `installDebug`가 모호하면 인자의 애플리케이션 ID에 맞는 디버그 variant 하나를 고른다(`installProdDebug`처럼). 프리뷰 화면은 `ui-tooling`을 디버그 의존성으로 넣은 빌드에만 있다. 같은 애플리케이션 ID의 다른 빌드가 설치되어 있어 서명이 달라 설치가 실패하면, 기존 앱을 지우지 않고 `skip`(설치 실패)으로 적는다.
3. **띄우기와 캡처**: 프리뷰마다 `adb shell am start -n {애플리케이션 ID}/androidx.compose.ui.tooling.PreviewActivity --es composable {프리뷰 전체 이름}`으로 띄우고 잠시 기다린 뒤 `adb exec-out screencap -p > .sdd-android/impl/{feature}/captures/{프리뷰 함수 이름}.png`로 받는다. 디렉터리는 `mkdir -p`로 만든다. 캡처가 빈 화면이면 프리뷰가 그려지기 전이다. 조금 더 기다려 같은 파일에 다시 받는다.
4. **기대 이미지**: 상태마다 대응하는 Figma 노드의 `get_screenshot`을 받는다.
5. **대조**: 캡처에는 상태 표시줄과 내비게이션 바, 제조사의 화면 요소가 함께 찍힌다. 이 영역은 뺀다. 기기에 따라 프리뷰가 상태 표시줄 아래에서 시작하기도 하고 맨 위부터 그려지기도 한다. 구성요소의 유무와 순서, 상태 표현, 문구, 눈에 띄는 색과 크기의 차이를 본다. 픽셀 단위의 차이는 보지 않는다.
6. 띄운 가상 기기는 끝나면 `adb emu kill`로 끈다. 연결되어 있던 실기기는 건드리지 않는다.

## 보고의 형식

마지막 메시지가 보고다. `{{skill:impl-orchestrator}}`가 이 보고를 그대로 CLI에 넘긴다.

```text
대조: 값 | 캡처
결과: design=pass|fail|skip
차이: (없으면 없음)
- {노드 ID} · {항목: 구성요소|문구|색|타이포|배치|상태} · Figma: {값} · 코드: {파일}:{줄} {값}
차이 파일: 저장소 루트 기준 경로를 쉼표로. 없으면 없음
spec이 정한 차이: spec이 Figma와 다르게 명시한 항목과 그 근거. 없으면 없음
미검증: 열지 못한 노드와 오류 문구. 없으면 없음
건너뛴 사유: skip일 때 (대조 대상 없음 | 기기 없음 | 설치 실패 | 권한 | 한도)
캡처: 받은 파일의 경로. 캡처의 대조일 때
증상: 실패를 한 줄로 (CLI의 --symptom에 들어간다)
```

통과를 꾸미지 않는다. 일부 노드만 열렸으면 열린 것만 판정하고 나머지는 미검증에 적는다.
