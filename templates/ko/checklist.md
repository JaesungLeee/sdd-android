# spec 품질 체크리스트

blueprint 단계로 넘어가기 전에 spec의 완성도와 품질을 검증한다. 모든 항목이 체크되어야 spec이 완료된다.

## 스펙 품질

- [ ] 구현 세부사항(언어, 프레임워크, API)이 없다
- [ ] 사용자 가치와 요구에 초점이 맞춰져 있다
- [ ] 개발자가 아닌 사람(기획자, 디자이너)이 읽을 수 있게 쓰였다
- [ ] 템플릿의 자리표시자와 주석이 남아 있지 않다

## 요구사항 완전성

- [ ] `TBD:`가 남아 있지 않다
- [ ] 요구사항이 검증할 수 있고 모호하지 않다
- [ ] 모든 사용자 스토리에 완료 조건과 테스트 시나리오가 있다
- [ ] 엣지 케이스가 식별되어 있다
- [ ] 범위가 명확히 한정되어 있다
- [ ] 가정이 적혀 있다

## 스펙 완성도

- [ ] 모든 기능 요구사항에 대응하는 테스트 시나리오가 있다
- [ ] 사용자 스토리가 주요 흐름을 빠짐없이 다룬다
- [ ] 성공 기준이 측정할 수 있고 기술 중립적이다
- [ ] 쓰인 조건부 섹션(UX 규칙, 주요 도메인, Figma 줄)이 이 feature에 해당한다
